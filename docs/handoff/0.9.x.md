# Handoff: the 0.9.x line (Kafka 0.9.0.1)

State at handoff: `0.9.x` == `0.8.x` after the cascade merge (`docs/CASCADE.md`). Everything a
Kafka 0.8.2.2 broker speaks is implemented and verified (687 tests: unit, 28 compliance vectors,
81 integration tests against a real broker). The pre-schema 0.9 code that used to live on this
branch (group-membership requests, Produce/Fetch v1 throttle time, Metadata v1, OffsetCommit v1
with member/generation, a first AdminClient — commits `04c9846..9219aeb`) was dropped in the merge
because it targeted the removed `pack()`/`unpack()` layer; its features are the tickets below, to
be re-implemented on the `BinarySchema` engine **starting from `main`'s classes**.

Read `CLAUDE.md` first (hard rules, toolchain, the Composer/phpstan sandbox workaround, Docker).

## Environment recipe for the session (do this first, it cost the 0.8 session an hour)

1. `nohup dockerd >/tmp/dockerd.log 2>&1 &` if `docker info` fails; then build and start the broker
   (first ticket below adds `docker/kafka-0.9.0.1/`; until then reuse `docker/kafka-0.8.2.2/` with
   `KAFKA_VERSION=0.9.0.1 KAFKA_DIST=kafka_2.11-0.9.0.1` build args — the 0.8 start script works for 0.9
   after adding `listeners=PLAINTEXT://0.0.0.0:9092`).
2. `tools/dev/vendor-from-source.sh` (Composer cannot download GitHub archives behind the proxy; the
   script installs from git sources and adds `phpstan.phar`). Copy `vendor/` into agent worktrees with `cp -a`.
3. **Probe the broker** for the supported api keys/versions with raw frames before writing tickets
   (send each key/version; a closed socket or `Unknown api code` in the broker log means unsupported).
   The 0.8 session did this for 0.8.2.2 and it corrected several assumptions.
4. Free disk: strip `.git` from vendor copies (the script does), and `docker system prune -f` between waves.

## Ticket plan (three waves, up to 4 Opus agents in isolated worktrees, coordinator reviews and merges)

Wave 1 — foundation (2 agents)
- **T1 broker + docs + surface**: `docker/kafka-0.9.0.1/` (+ compose, readiness probe check), `docs/protocol/0.9.0.md`
  (grammar of everything above, api-key table, error table −1..31, quirks), api-key/version probe results,
  `ApiKeys` 11–16, error classes 21–31 + code 13 → `NetworkException` (from `main`), `ConsumerConfig` options
  restored, README/CHANGELOG headers switched to 0.9.x, CI (`ci.yml` already triggers on `0.*.x`).
- **T2 versioned schemes**: Produce v1, Fetch v1 (throttle time), OffsetCommit v2 (`retentionTime`, no per-partition
  timestamp), ControlledShutdown v1 — version-aware `getScheme()` (pattern: `OffsetCommitRequest`/`…V0`), `Client`
  chooses the highest version the broker supports (0.9 → v1/v2), compliance vectors captured from the broker.

Wave 2 — group protocol and transport (4 agents)
- **T3 group membership messages**: JoinGroup/SyncGroup/Heartbeat/LeaveGroup v0 + `ConsumerProtocol`
  (Subscription/MemberAssignment schemes, versioned), hex vectors, integration tests that join a group with a
  raw request sequence and observe generation/member ids.
- **T4 admin group apis**: ListGroups/DescribeGroups v0 + `AdminClient::{describeGroup,listGroups,listAllGroups}`
  (from `main`), README admin section.
- **T5 SSL transport**: backport `SecurityProtocol`/`SslProtocol`/`ClientConfig::SSL_*`/`SocketStream` crypto
  from `main`; broker container with an SSL listener (self-signed keystore generated at build); integration test.
- **T6 client group methods**: `Client::{joinGroup,syncGroup,heartbeat,leaveGroup}` from `main` with correlation
  ids/`RetryPolicy` (retry 14/15/16, surface 22/25/27 to the caller), `CoordinatorLookup` reuse.

Wave 3 — clients and docs (3–4 agents)
- **T7 KafkaConsumer group membership**: `subscribe()`/`unsubscribe()`/`subscription()`, rebalance flow
  (JoinGroup → leader runs the assignor → SyncGroup → positions from committed offsets), heartbeat driven from
  `poll()` (PHP has no background thread — heartbeat when `heartbeat.interval.ms` elapsed, rejoin on 27/25/22),
  `LeaveGroup` on `close()`/destruct, commits carry generation + member id, Range and RoundRobin assignors,
  two consumers in one group splitting partitions in an integration test.
- **T8 producer/consumer v1 plumbing**: throttle time exposed (`RecordMetadata`/fetch results), `offset.retention.ms`,
  `Client::fetchPartitions()` carrying `throttleTimeMs`.
- **T9 docs/compliance**: `docs/protocol/0.9.0.md` vectors + `tests/Compliance`, README compatibility matrix for
  0.9.0.1, CHANGELOG, examples (`examples/consumer-group.php`), `docs/CASCADE.md` history row for 0.9.x → 0.10.x.

Each ticket: byte-exact tests, integration tests against the 0.9.0.1 broker with unique topic/group names,
`composer check` + full integration suite green before the PR, PR against `0.9.x` with "Closes #n".
Coordinator gate before merging: local cs/phpstan/unit/compliance/integration on the PR merged with the
current base, CI green, then merge commit and close the issue by hand.

## Pitfalls seen in the 0.8 session (avoid repeating)

- Composer + GitHub proxy (see above); pointing Composer at mirrors is blocked by the sandbox policy.
- phpstan is a phar (`php vendor/bin/phpstan`), level 0, `new.static` ignored by identifier in `phpstan.neon`.
- Nested branch names (`0.9.x/foo`) cannot exist next to branch `0.9.x` — use `t<n>-<slug>`.
- Agents editing the same file in parallel (e.g. `Client.php`, test helpers) — assign file ownership per ticket and
  freeze shared contracts for a wave; merge the base into a PR before its gate when another PR landed first.
- A 0.8/0.9 broker: zero brokers in Metadata on a topic-less cluster; fresh topics answer 5/6 for a moment;
  Fetch truncates mid-message at MaxBytes; OffsetFetch v0 vs v1 differ for uncommitted partitions.
- GitHub `issue_write` with "Closes #n" does not auto-close on non-default branches — close issues manually.
- Merge PRs with `expectedHeadSha` (full 40-char SHA); agents often push again after reporting.
